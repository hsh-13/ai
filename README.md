## 현재 기능 (프로토타입 v4.3)
- **일정:** 등록·수정·삭제, 진행 상태, 단계별 진행, 종류 필터, 마감순·우선순위순 정렬, 카드 접기·펼치기. 우선순위는 마감 50%·중요도 30%·소요 시간 20% 규칙 점수
- **가용 시간:** 요일별 기본값, 날짜별 수정(날짜별 값이 우선), 개인 약속은 입력한 `줄일 시간`만큼 그날 가용 시간에서 차감(시각은 입력하지 않음)
- **주간 부하·계획:** 마감일부터 거꾸로 단계 단위로 가용 시간에 배정(v4.3부터 그 일정에 연결해 공부한 시간은 남은 소요 시간에서 빼고, 오늘 공부한 시간은 오늘 가용 시간에서 먼저 쓴 것으로 계산), 날짜별 여유·빠듯(가용 시간의 90% 이상)·부족 표시, 부족 시간과 조정 방법
- **오늘 화면:** 오늘 할 일 체크리스트(체크하면 진행에 반영), 앞으로 7일 판단, 코멘트(기본은 규칙 기반, 서버 연결 시 "AI로 받기" 버튼)
- **공지 붙여넣기 추출:** 3단계(붙여넣기 → 확인 → 단계). 요구사항마다 원문 근거 확인, "확인 필요" 표시. 날짜 계산은 코드가 한다. AI(Gemini)가 추출하고, 실패하면 결과를 쓰지 않고 실패 화면에서 재시도·규칙 기반(정규식)·직접 입력을 고를 수 있다. 공지 하나에서 일정이 여러 개 나오면(최대 5개) 1/3, 2/3처럼 하나씩 확인해 추가하고, 건너뛸 수 있으며 이미 추가한 일정은 남는다
- **계정·저장:** 닉네임+비밀번호 계정(앱 시작 화면이 로그인), 계정별 데이터 분리. `AI_ENDPOINT`가 설정돼 있어 서버 모드로 동작하며 계정과 일정이 구글 시트에 저장된다(`apps-script/`). 서버 주소가 비어 있으면 브라우저 localStorage에만 저장한다. 로그인·시트 저장은 팀원이 테스트로 확인했다
- **공부 타이머:** 홈 캐릭터 카드에서 시작, 1분 = 1 XP, 한 번에 최대 120분 인정, 1분 미만 미기록, 레벨 L→L+1에 60+30×(L−1) XP(숫자는 팀이 임의로 정한 값). 본인이 누르는 방식이라 실제 공부 여부는 확인할 수 없음.
- **공부 게임(고양이 모으기):** 레벨이 오를 때마다 상자 1개. 보상은 고양이 2마리와 액세서리 15개 중 아직 없는 것이고, 회색 고양이는 처음부터 가진다. 희귀도는 일반·희귀·에픽 70/25/5(임의로 정한 값)이며 다 모은 등급은 빼고 남은 것끼리 비율을 다시 계산한다. 보상은 레벨업 때 정해져 새로고침해도 바뀌지 않고, 상자는 타이머가 멈춰 있을 때만 연다. 꾸미기 화면에서 고양이를 바꾸고 머리·얼굴·등 액세서리를 입힌다. 외형만 바뀌며 경험치·계획·가용 시간 계산에는 영향이 없다. 그림은 Last tick 작가의 무료 팩이다(아래 "에셋 출처")
- **디자인(v4.1):** 고양이 그림에 맞춘 레트로 픽셀 느낌. 굵은 테두리·계단식 그림자·각진 모서리, 차콜·크림·호박색. 여유·빠듯·부족 상태 색과 AI 보라색은 의미가 있어 유지했다. 색은 `CSS/style.css` 맨 아래 v4.1 블록의 변수에서 바꾼다
- **기타:** 예시 데이터 넣기·삭제, 처음 방문 사용법 5장(공부 타이머 안내 포함, 오늘 화면 ? 버튼으로 다시 보기), 이용 약관·개인정보 안내(수업용 문구, 법적 효력 없음)

버전별 변경 상세는 `CHANGELOG.md`에 있습니다.

## AI 연결 방식
`JS/app.js`의 `AI_ENDPOINT`(현재 Apps Script 웹 앱 주소가 설정됨)로 POST 요청을 보낸다. 주소가 비어 있으면 AI 없이 규칙 기반으로만 동작한다. 화면에는 "AI" 또는 "규칙 기반"으로 표시한다. Gemini API 키는 프론트엔드 코드에 넣지 않고 중계 서버(Apps Script 스크립트 속성)에서만 보관한다. AI가 429·500·503으로 응답하면 서버가 1.2초 뒤 한 번 다시 시도하고, 그래도 안 되면 모델을 `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` 순으로 바꿔 시도한다(`gemini-2.5-flash-lite`는 구글이 종료해 2026-11-23에 목록에서 뺐다. 모델 이름은 2026-11 기준이며 바뀔 수 있다). 날짜·시간 계산은 항상 코드가 하고, AI는 추출과 문장 생성만 맡는다. 응답은 코드가 형식을 검증하며, 맞지 않으면 결과를 쓰지 않고 실패 화면(다시 시도 / 규칙 기반 / 직접 입력)을 보여 준다.

| task | 요청 | 응답(JSON) |
|---|---|---|
| extract | `{task, text, today}` | `{items:[일정,...](최대 5), omitted}`. 일정 하나는 `{title, type, importance, effort(30/60/120/180/300), deadline(null 또는 absolute/relative_week/relative_days + evidence), requirements:[{text, evidence}]}`. 첫 일정은 최상위에도 복사해 이전 형식 앱도 읽을 수 있고, AI가 배열이나 객체 하나로 답해도 서버가 이 형식으로 맞춘다 |
| comment | `{task, today:[{title,hours}], shortages:[{title,shortHours,days}]}` | `{comment}` |

## 현재 한계
- **공부 시간 반영(v4.3):** 타이머를 시작할 때 일정을 고르지 않으면 그 공부는 어떤 일정의 남은 시간도 줄이지 않는다(오늘 가용 시간에서만 차감). 한 번에 최대 120분만 인정하는 기존 규칙도 그대로다. 휴대폰에서는 확인하지 않았다.
- **AI 연동:** 팀에서 연동 완료를 확인했으나 확인한 범위(성공 호출 수, 응답 시간)는 기록하지 않았다. 화면의 응답 대기 한도는 25초이고, 첫 호출 지연은 측정하지 않았다. 재시도·모델 전환이 실제로 몇 번 일어났는지 기록하지 않았다. 서버에는 하루 AI 요청 200회 한도(임의로 정한 값)가 있고, 이 숫자는 우리 서버가 스스로 세는 것이라 구글 AI Studio가 모델별로 거는 하루 한도(팀원 확인 시 500)와는 별개이며 먼저 닿는 쪽이 상한이다(분당 한도는 15라 동시에 여러 명이 쓰면 429가 날 수 있다). 2026-11-23 서버 수정 전에는 이 카운터가 캐시에 저장되어 6시간 안에 초기화될 수 있었다(구글 문서 기준 추정). **AI 호출(공지 추출·코멘트)에는 로그인 검증이 없어** 웹 앱 주소를 아는 사람은 누구나 호출할 수 있고 하루 한도로만 제한된다.
- **공지 하나에 일정이 여러 개일 때:** 최대 5개까지 하나씩 확인해 추가한다. 5개를 넘으면 나머지는 버려지므로(`omitted`) 다시 붙여넣어야 한다. AI가 일정 종류를 잘못 분류할 수 있어 확인 화면에서 직접 고쳐야 한다.
- **서버 저장:** 로그인·시트 저장은 팀원이 테스트로 확인했으나 확인한 범위는 기록하지 않았다. 시트를 열 수 있는 사람은 닉네임과 일정 데이터를 볼 수 있고, 비밀번호는 해시로 저장된다(`apps-script/SETUP.md` 한계 참고).
- **규칙 기반 추출(AI가 안 될 때 쓰는 대체 경로):** 키워드 방식이다. 일정 종류는 공지 첫 줄(제목)에서 먼저 나오는 종류 단어를 따르고, 제목에 없으면 본문 전체에서 찾는다. 영어 공지와 날짜가 없는 공지는 마감을 찾지 못한다. 확인 화면에서 사용자가 고치게 되어 있다. AI 경로의 분류 정확도는 따로 측정하지 않았다.
- **계획 배정 방식:** 마감일에 가까운 날부터 거꾸로 채우므로, 마감이 며칠 뒤이고 가용 시간이 넉넉하면 오늘 배정이 비어 있을 수 있다. 오류가 아니라 설계이다.
- **자정을 넘겨 화면을 켜 둔 경우:** 탭을 한 번 옮기기 전까지 오늘 날짜가 바뀌지 않는다(자동 갱신 없음).
- **움직임 줄이기:** 기기 설정에서 움직임 줄이기가 켜져 있으면 고양이 애니메이션(앉기·잠자기 등)이 멈추고 앉은 그림만 보인다. 접근성을 위한 의도된 동작이다.
- **기능:** 파일 OCR, URL 분석은 구현하지 않았다. 공부 타이머는 본인이 누르는 방식이라 실제 공부 여부를 확인할 수 없다. 고양이 게임은 휴대폰에서 오늘 화면만 확인했고(나머지 화면과 두 기기 동기화는 시험하지 않았고), 그림을 공개 저장소에 올려도 되는지 작가 답변을 받지 못했다(아래 "에셋 출처").
