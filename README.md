# AI 학업 플래너 프로토타입

마감이 겹친 주를 미리 보여주고, 내 가용 시간 안에서 현실적인 우선순위를 알려주는 학업 일정 앱.

## 디렉토리 구조

```text
.
├── index.html            # 최신 프로토타입 (GitHub Pages 진입점)
├── CSS/style.css
├── JS/app.js
├── wireframe/            # 10주차 와이어프레임 버전
├── apps-script/Code.gs   # AI 중계 서버 초안 (Apps Script → Gemini, 배포·호출 테스트 전)
└── prototyping/          # 프로토타입 버전별 단일 파일 (v1, v2, v2.1, v2.2, v2.3, v3.0, v3.1, v3.2)
```

## 실행 방법
`index.html`을 브라우저에서 열면 됩니다. GitHub Pages: Settings → Pages → Branch `main` / `/ (root)`.

## 현재 기능 (프로토타입 v3.2)
**v3.2 변경 (로그인 시작)**
- 앱 시작 화면이 로그인(닉네임+비밀번호). 로그인 전에는 오늘/계획/일정/마이로 이동할 수 없고 이용 약관·개인정보 안내만 볼 수 있음. 가입은 로그인 화면의 "처음이에요, 회원가입"
- 계정은 아직 이 브라우저(localStorage)에만 저장됨. 다른 기기·브라우저에서는 같은 닉네임으로 로그인할 수 없음
- 저장 코드는 `JS/app.js`의 `Store` 객체 한곳에 모아 둠(구글 시트 연동 때 교체할 지점)

**v3.1 변경 (디자인)**
- 폰트 Pretendard(CDN), 기본 글자 15px, 보조 글자 최소 13px
- 주간 막대그래프: 막대 위 시간 숫자, 검은 선 = 내 가용 시간, 범례 표시
- 상단 헤더 그라데이션, 배경·카드 색감 조정

**v3.0에서 구조·디자인 개편**
- 하단 탭 5개: 오늘 / 계획 / ＋ 추가 / 일정 / 마이. AI 분석 탭은 없애고 우선순위는 일정 목록에, 코멘트는 오늘 화면에 넣음
- 오늘: 오늘 할 일 체크리스트(체크하면 단계·일정 진행에 반영), 앞으로 7일 판단 카드(여유·빠듯·부족, 규칙 계산), 코멘트(AI 서버 연결 시 AI, 아니면 "규칙 기반"으로 표시)
- 계획: 주간 스트립(날짜별 여유·빠듯·부족 점) → 선택한 날의 가용 시간(기본 − 약속)·배정·부족, 단계 배정 타임라인, 개인 약속(빗금), 배정하지 못한 시간과 조정 방법, 날짜별 가용 시간 수정, 주간 부하 막대
- 일정: 종류 필터, 마감순/우선순위순 정렬, 우선순위 번호(규칙 계산)·단계 진행·부족 시간 표시. 일정 상세에서 우선순위 근거와 요구사항·단계 확인
- 공지로 일정 추가를 3단계(붙여넣기 → 확인 → 단계)로 분리하고 단계 제안 화면에 "배정 미리보기"(마감일부터 거꾸로 가용 시간에 배정한 날짜) 추가
- 디자인: 밝은 배경 + 코발트 포인트, AI 결과는 보라 태그·규칙 계산은 테두리 태그로 구분, 상태 색(여유 초록·빠듯 주황·부족 빨강) 고정, 본문 14px·최소 12px, 조작 영역 44px 이상. 구조·디자인 시안은 와이어프레임 캔버스 v0.7 기준

**v3.0 공지·단계·약속 기능**
- 공지 붙여넣기 추출 개편: 2,000자 입력 제한과 글자 수 표시, 계산 기준일 안내, 외부 전송 안내, 대기 화면(취소 가능·10초 제한)
- 추출 결과 확인 화면: 요구사항마다 원문 근거 문장을 보여주고 코드가 원문에 실제로 있는지 확인("근거 확인됨/근거 없음")
- 상대 날짜("다음 주 금요일")는 AI가 표현만 구조화하고 실제 날짜는 코드가 기준일로 계산
- "확인 필요" 표시: 날짜 없음·상대 날짜·지난 날짜·날짜 여러 개·근거 없는 요구사항
- 실패 처리: 시간 초과·응답 오류·형식 불일치면 결과를 쓰지 않고 다시 시도 / 규칙 기반 추출 / 직접 입력 중 선택
- 단계 제안: 요구사항을 고정 단계 유형(분량 점검·제출 등)에 연결하고 일정 종류별 기본 단계를 더해 제안, 소요 시간은 "추정"이며 수정 가능. 공지에 없는 단계는 만들지 않음
- 배정이 단계 단위로 동작(마지막 단계가 마감에 가장 가깝게 배정). 오늘 이미 끝낸 시간은 오늘 가용 시간에서 먼저 쓴 것으로 계산
- 개인 약속: 날짜·시간을 입력하면 그날 가용 시간에서 코드가 뺌(날짜별 직접 수정값이 있으면 그 값 우선). 약속 내용은 AI로 보내지 않음
- 일정 등록의 파일 업로드·URL 입력 탭 제거(미구현이었음)

**v2.3까지의 기능**
- 일정 등록·수정·삭제, 진행 상태 변경
- 요일별 가용 시간 입력 (마이 페이지)
- 주간 부하 막대 (홈·일정): 마감일부터 거꾸로 가용 시간에 배정하고, 배정하지 못한 시간은 빨간색 `+Nh`로 표시
- 규칙 기반 우선순위 계산 (마감·중요도·소요 시간, v3.0부터 일정 목록에서 항상 계산)
- 예시 데이터 넣기/삭제 (예시 일정에는 "예시" 표시)
- 오늘 할 일 자동 배정: 부하 계산 결과에서 오늘 몫을 보여줌
- 조정이 필요한 일정 안내: 부족한 시간과 하루 추가 확보량을 코드가 계산해 표시
- 특정 날짜만 가용 시간 수정 (일정 화면): 알바·약속 등 불규칙한 날 대응
- 공지 붙여넣기 → 일정 추출: 결과는 입력 폼에 채워지고 사용자가 확인·수정한 뒤 저장
- AI 코멘트: 오늘 할 일과 부족 시간을 문장으로 요약
- 화면 디자인(v2.3): 홈 상단 판단 카드(이번 주 부하 링·요약), 요약 숫자 3개(전체 일정·완료율·가장 가까운 마감), 종류별 색·아이콘·D-day·중요도 점이 있는 일정 카드, 일정 화면 주간 스트립(날짜별 여유·빠듯·부족 점), 분석 순위 카드, 일정 추가 버튼(+)
- 마이 페이지: 닉네임·비밀번호 회원가입/로그인/로그아웃/계정 삭제(이 브라우저 안의 로컬 계정이며 서버 인증 아님, 비밀번호는 해시로 저장), 계정별 일정·가용 시간·분석 결과 분리, 이용 약관, 개인정보 취급 안내

## AI 연결 방식
`JS/app.js`의 `AI_ENDPOINT`가 비어 있으면 규칙 기반 Mock으로 동작하고, 화면에 "Mock" 또는 "AI"로 표시된다. 주소를 넣으면 중계 서버로 POST 요청을 보낸다. Gemini API 키는 프론트엔드 코드에 넣지 않고 중계 서버에서만 보관한다.

| task | 요청 | 응답(JSON) |
|---|---|---|
| extract | `{task, text, today}` | `{title, type, importance, effort(30/60/120/180/300), deadline(null 또는 absolute/relative_week/relative_days + evidence), requirements:[{text, evidence}]}` |
| comment | `{task, today:[{title,hours}], shortages:[{title,shortHours,days}]}` | `{comment}` |

요청은 `text/plain`으로 보내 CORS 사전 요청을 피하고, 응답은 코드가 형식을 검증한다. 실패하면 결과를 쓰지 않고 실패 화면에서 재시도·규칙 기반 추출·직접 입력을 고르게 한다. `AI_ENDPOINT`가 비어 있으면 처음부터 규칙 기반(Mock)으로 동작한다. 날짜·시간 계산은 항상 코드가 하고, AI는 추출과 문장 생성만 맡는다.

## 참고
- 현재 `AI_ENDPOINT`가 비어 있어 추출·코멘트는 모두 Mock(규칙 기반)입니다. Gemini 연동 코드(`apps-script/Code.gs`)는 초안이며 배포·실제 호출 테스트를 하지 않았습니다. 파일 OCR, URL 분석은 구현하지 않았습니다.
- 데이터는 브라우저 localStorage에 저장됩니다.
