# 구글 시트 연동 설정 (2026-11-23 갱신)

앱의 계정·일정을 구글 시트에 저장하려면 아래 순서로 한 번만 설정한다. 소요 시간은 10~15분 정도이다.
`JS/app.js`의 `AI_ENDPOINT`가 비어 있으면 앱은 이전처럼 이 브라우저에만 저장하며, 아래 설정은 하지 않아도 앱이 동작한다.

## 먼저 정할 것
- **시트와 Apps Script를 만드는 사람은 팀원 한 명**이다. 그 사람의 구글 계정으로 실행되고, 그 사람의 구글 드라이브에 시트가 생긴다.
- 시트를 열 수 있는 사람은 모든 사용자의 닉네임과 일정 데이터를 볼 수 있다. 팀원을 공유하는 범위는 필요한 사람만으로 한정한다.
- 이 시트에는 팀 프로젝트 시연용 데이터만 넣는다. 실제 학업·개인정보는 넣지 않는다.

## 1. 구글 시트 만들기
1. https://sheets.google.com 에서 빈 스프레드시트를 만든다. 이름은 `AI 학업 플래너 DB` 등 아무거나.
2. 탭을 직접 만들 필요는 없다. 첫 요청 때 `users` 탭이 자동으로 생긴다.

## 2. Apps Script 붙여넣기
1. 시트 메뉴 **확장 프로그램 → Apps Script**를 연다. (시트에 연결된 스크립트가 된다.)
2. 기본 `Code.gs` 내용을 모두 지우고, 이 저장소의 `apps-script/Code.gs` 전체를 붙여넣는다. 저장(Ctrl+S).
3. 왼쪽 **프로젝트 설정(톱니바퀴) → 스크립트 속성 → 속성 추가**
   - `cnt_ai`, `cnt_acc` = 하루 요청 횟수 카운터. 서버가 자동으로 만들고 갱신하므로 직접 만들거나 지우지 않는다.
   - `GEMINI_API_KEY` = Gemini API 키 (AI 기능을 쓸 때만. 계정·저장 기능에는 필요 없다.). 키는 스크립트 속성에만 넣고 저장소·앱 코드에는 넣지 않는다.
   - 시트에 연결하지 않고 독립 스크립트로 만들었다면 `SHEET_ID` = 시트 주소의 `/d/` 와 `/edit` 사이 값

## 3. 웹 앱으로 배포
1. 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**
2. 설명은 아무거나, **다음 사용자로 실행: 나**, **액세스 권한: 모든 사용자**
3. **배포**를 누르고 권한 승인 화면에서 본인 계정을 선택해 허용한다. ("확인되지 않은 앱" 경고가 나오면 고급 → 이동을 눌러 진행한다. 본인이 만든 스크립트이다.)
4. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사한다.

> `Code.gs`를 고쳐 다시 배포할 때는 **배포 관리 → 편집(연필) → 버전: 새 버전**으로 해야 같은 URL이 유지된다. "새 배포"를 하면 URL이 바뀐다.

## 4. 앱에 연결
1. `JS/app.js` 맨 위 근처의 `const AI_ENDPOINT='';` 를 `const AI_ENDPOINT='복사한 URL';` 로 바꾼다.
2. GitHub에 올리고 Pages가 갱신되면(Ctrl+F5) 로그인 화면 안내가 "팀이 만든 구글 시트에 저장돼요"로 바뀐다.

## 5. AI 모델 설정 (공지 추출·코멘트를 쓸 때)
- `Code.gs` 위쪽의 `MODEL`(기본 모델)과 `MODELS`(전환 순서)에 모델 이름이 있다. 현재 `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` 순이다(2026-11 기준, 모델 이름은 바뀌거나 없어질 수 있으니 오류가 나면 구글의 모델 목록에서 확인한다). 팀원 확인(2026-11-23): 두 모델 모두 사용 가능하다. `gemini-2.5-flash-lite`는 구글이 2026-10-16에 종료한 모델이고 호출하면 404가 나서 목록에서 뺐다. 이름이 없는 모델(404)은 코드가 재시도 없이 다음 모델로 넘어간다.
- `Code.gs` 맨 끝에 Apps Script 편집기에서 직접 실행하는 테스트 함수 3개가 있다(`testGeminiModelsOnce`, `testFallbackTo31`, `testCallGeminiFallback`). 웹 앱 요청(`doPost`)에서는 호출되지 않아 앱 사용자는 실행할 수 없다. 실행하면 Gemini를 호출해 한도를 쓰고, `testGeminiModelsOnce`는 종료된 2.5 lite도 확인 대상에 넣어 두었다. `callGemini_`는 선택 인자로 모델 목록을 받을 수 있게 되어 있고, 앱의 일반 요청은 인자 없이 호출하므로 `MODELS`를 그대로 쓴다.
- AI가 429·500·503을 돌려주면 1.2초 뒤 한 번 재시도하고, 그래도 안 되면 다음 모델로 넘어간다. 모든 모델이 실패하면 앱 실패 화면에 `upstream_코드`가 보인다.
- 공지 하나에서 받는 일정은 `MAX_ITEMS`(5)개까지다. 하루 AI 요청 한도 `DAILY_LIMIT` 200은 임의로 정한 값이다. 이 횟수는 스크립트 속성 `cnt_ai`에 날짜와 함께 저장된다(2026-11-23 수정 이후). 구글 AI Studio에 표시되는 모델별 하루 한도(확인 시 500)와는 별개이며 먼저 닿는 쪽이 상한이다. 분당 한도(확인 시 15)가 있어 여러 명이 동시에 쓰면 429가 날 수 있다.
- 모델 이름이나 키를 바꾼 뒤에도 **배포 관리 → 편집 → 새 버전**으로 다시 배포해야 반영된다.

## 6. 동작 확인
- [ ] 회원가입 → 시트 `users` 탭에 행이 생긴다. `hash` 칸에 비밀번호 원문이 아니라 긴 문자열이 있다.
- [ ] 예시 일정을 불러온 뒤 1~2초 지나 마이 탭에 "서버에 저장됨"이 보이고, `data` 칸에 JSON이 있다.
- [ ] 휴대폰 등 다른 기기에서 같은 닉네임으로 로그인하면 같은 일정이 보인다.
- [ ] 계정 삭제 → 시트 행이 사라진다.
- [ ] 공지를 붙여넣어 일정이 추출되는지 본다. 일정이 여러 개인 공지는 "1/3"처럼 하나씩 확인 화면이 나온다.
- [ ] 로그인 응답이 몇 초 걸리는지 본다. 3초를 넘어도 **`HASH_ROUNDS` 값을 바꾸지 않는다.** 저장된 해시에 반복 횟수가 기록되지 않아서, 값을 바꾸면 이미 만들어진 계정이 모두 로그인되지 않는다. 꼭 바꿔야 한다면 시트 `users` 탭을 비우고 모두 다시 가입시킨다. (응답 시간은 실제 배포 후에도 측정하지 못했다.)

## 한계 (발표·문서에 그대로 적을 것)
- AI 호출(공지 추출·코멘트)에는 로그인 검증이 없다. 웹 앱 주소를 아는 사람은 호출할 수 있고, 하루 한도로만 제한된다.
- 비밀번호는 HTTPS로 Apps Script에 전달되어 서버에서 해시(소금 + 반복 SHA-256)로 저장된다. bcrypt 같은 전용 방식은 Apps Script에서 쓸 수 없고, 보안 검증을 거친 서비스가 아니다.
- 시트를 볼 수 있는 팀원은 닉네임과 일정 데이터를 읽을 수 있다. 로그인 토큰은 해시로만 저장되어 시트에서 세션을 빼낼 수 없다.
- 한 계정당 5대까지 동시에 로그인할 수 있고, 6번째 기기를 로그인하면 가장 오래된 기기가 로그아웃된다. 로그인 유지는 7일이다.
- 닉네임별로 로그인 5회 실패 시 10분간 잠긴다. 일일 요청 한도(`ACCOUNT_DAILY_LIMIT` 3000)는 임의 값이다.
- 두 기기에서 동시에 고치면 마지막에 저장한 쪽이 충돌 안내를 받고, 덮어쓰기와 불러오기 중에서 고른다. 항목 단위 병합은 하지 않는다.
- 저장 데이터는 한 계정당 4만 5천 자까지이다(시트 한 칸 한도 5만 자 미만). 일정이 아주 많으면 저장이 거부된다.
- 공부 게임 데이터(고양이·액세서리·공부 기록)도 같은 저장 칸에 들어가며, 서버에는 게임 전용 코드가 없고 앱이 보낸 JSON을 그대로 저장한다. 공부 기록은 최근 150건만 남겨 한도를 넘지 않게 했다.
- Apps Script 응답은 첫 호출이나 한동안 쓰지 않은 뒤에 느릴 수 있다(콜드 스타트). 이 지연은 측정하지 않았다.
